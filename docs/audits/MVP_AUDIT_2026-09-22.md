# Auditoria do MVP — 22/09/2026

## Escopo e limitações da execução

A auditoria começou com a árvore Git limpa, na branch `work`. O contêiner não possui o
SDK `dotnet`, Docker nem `psql`; portanto, build .NET, testes automatizados, migrations,
seed e login HTTP não puderam ser executados neste ambiente. A inspeção estática não é
tratada como validação de runtime. `npm run build` validou os assets web existentes.

## Correções aplicadas nesta entrega

- A identidade de um usuário comum só é carregada quando há vínculo ativo com ao menos
  um tenant ativo e não excluído. Superadministradores continuam independentes de
  vínculo de tenant.
- A validação de sessões passou a revogar efetivamente o acesso na requisição seguinte
  quando todos os tenants do usuário forem suspensos/inativados.
- Foi criado teste de integração para recusar novo login e token já emitido depois da
  suspensão do tenant de demonstração.
- Links de navegação e atalhos que levavam apenas a páginas de “em construção” foram
  removidos. Funcionalidades reais e autorizadas continuam no menu.
- Dashboard, catálogo de planos e seleção de organizações receberam instruções de uso
  objetivas ou aprimoradas.

## Validação manual necessária

Em uma estação com .NET 10.0.400 e PostgreSQL 18:

1. Execute restore, build e testes conforme o `README.md`.
2. Migre um banco limpo e outro já existente; execute o seed duas vezes.
3. Entre com as duas credenciais reservadas e conclua troca de senha/MFA quando exigidos.
4. Com o cliente autenticado, altere o tenant de demonstração para `suspended`: um novo
   login e a próxima chamada com o token anterior devem retornar 401.
5. Restaure o tenant para `active`, bloqueie o membership e repita o cenário.
6. Percorra os menus desktop e móvel de Superadministrador e cliente, verificando que
   somente fluxos disponíveis e permitidos aparecem.

## Pendências e próxima sprint recomendada

Priorizar uma fatia vertical de administração global: usuários/perfis, contratos e
auditoria filtrável, sempre com API autorizada, persistência, exclusão lógica, auditoria,
testes de isolamento e UI completa. Depois, implementar faturamento manual e gestão de
assinaturas antes de recolocar esses itens no menu. Completar as áreas “Como usar” nas
telas operacionais restantes e executar uma rodada E2E responsiva e de acessibilidade.
